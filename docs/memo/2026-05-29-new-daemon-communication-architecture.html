BuddySwitch daemon team memo · 2026-05-29

新 daemon 通讯升级架构

目标是先把 daemon 升级成清晰、独立、可验证的运行时通讯层：central daemon 负责 presence、可达性和事件投递；每个 instance daemon 负责本地 mailbox 消费和目标侧 action trigger；message 只消费这些能力，不把身份、在线状态和投递逻辑揉在一起。

central daemon 独立进程 RuntimeActorAddress 唯一地址语言 显式 instance 级发送 event 只传引用

Daemon 团队当前主线

先交付 daemon 通讯底座，再让 message 在这个底座上升级。
  • 不 ownsbuddy identity、message durable data、message 业务 UI/SOP。
  • 必须 ownspresence registry、reachability、mailbox、event delivery、daemon-side trigger。
  • 关键原则简单直接，但不是临时拼接；独立进程与清晰边界必须成立。
架构总览 数据链路 对外能力 契约样例 边界归属 实施顺序

1. 升级后架构总览

daemon 不重新发明 buddy 身份体系，只消费 actor_profile 的 actor address，并把所有在线通讯事实集中到 central daemon。

actor_profile

identity

唯一产出 runtime actor address：RuntimeActorAddress(buddy_id, instance_id)。不保存 endpoint、heartbeat、status。

message module

consumer

提供 message.contacts、message.send、message.list。message.send 使用明确 target_actor_address。

central daemon process

single runtime authority

一个 shared-root 级独立进程。所有 instance daemon 注册到这里；工具和模块通过它查询在线联系人、确认目标可达性、投递 reference-only event。

presence registry
online contacts query
target reachability check
event delivery to instance mailbox

instance daemon A

sender side

启动后注册自己的 actor_address 和 mailbox endpoint；作为当前 buddy runtime 的后台服务。

instance daemon B

target side

接收 mailbox event，消费 message.available，通过自己的 ActionGateway 触发目标 buddy 读取消息。

地址事实actor_profile 负责。
在线事实central daemon 负责。
消息数据message module 负责。
触发动作target instance daemon 负责。

2. 整体数据链路

第一版只需要把主路径做清楚。contacts 是发现能力，不是强制 SOP；send 是显式 actor address 发送，不再做模糊 to_buddy 解析。

A. Daemon 启动注册链路

presence source of truth
1

实例 daemon 启动

launcher 启动当前 buddy instance daemon。

2

生成 actor address

daemon 调用 actor_profile，拿到本地 RuntimeActorAddress。

3

注册到 central daemon

提交 actor address、mailbox endpoint、heartbeat/status。

4

维持心跳

central daemon 记录 last_seen_at，判断 online/offline。

5

退出标记 offline

正常 unregister；异常退出由 heartbeat TTL 收敛为 offline。

B. message.contacts 联系人查询链路

optional discovery
1

buddy 自主查询

不确定可联系对象时，调用 message.contacts。

2

传入 filter

可按 buddy_id 过滤；filter 不是发送目标解析。

3

central daemon 查询

只返回当前 online/sendable 的 actor address 列表。

4

message 工具反馈

反馈联系人、状态、last_seen_at 等决策字段。

5

buddy 决策

buddy 可选择某个明确 target_actor_address 再发送。

C. message.send 在线发送链路

explicit instance-level communication
1

显式目标地址

message.send 接收 target_actor_address 和 content。

2

可达性确认

message 调 central daemon 检查目标是否 online/sendable。

3

创建 durable message

仅目标在线时创建 message object，数据归 message 模块。

4

投递事件

central daemon 投递 message.available 到目标 mailbox。

5

返回工具反馈

返回 message_id、delivery status、target actor address。

D. 目标 daemon 消费链路

mailbox to action trigger
1

mailbox 收到 event

event 只包含 message_id 与 actor address 引用。

2

校验目标

target daemon 确认 to_actor_address 是自己。

3

调度读取动作

把 event 转成订阅/定时动作，而不是直接搬运正文。

4

ActionGateway

通过当前 daemon 的 ActionGateway 触发目标 buddy 读取消息。

5

message.list

目标 buddy 使用 message 工具读取 durable inbox。

reachability status

状态含义message 反馈建议
online目标 actor_address 当前在线且可投递。继续创建 message 并投递 event。
registered_offline目标曾注册，但当前无有效心跳或已退出。target_not_online，不创建 message。
never_registeredcentral daemon 没见过该 actor_address。target_not_online，附带原因。
invalid_actor_addresspayload 不满足 actor_profile address contract。invalid_target_actor_address。

delivery status

状态含义message object
deliveredevent 已进入目标 daemon mailbox。已创建。
delivery_failed目标 reachability 已通过，但 mailbox 投递失败。保留，不回滚。
target_not_onlinereachability 未通过。不创建。
invalid_target_actor_address地址 payload 非法。不创建。

5. 边界归属

这部分是防止实现时跑偏的约束。daemon 的独立性来自清楚 owns 什么，也来自清楚不 owns 什么。

actor_profile

  • owns actor address contract
  • to_payload() / from_payload()
  • 不含 presence fields

central daemon

  • owns registry / presence
  • owns contact query
  • owns reachability / delivery

instance daemon

  • owns local mailbox
  • owns event consumption
  • owns ActionGateway trigger

message

  • owns contacts/send/list tools
  • owns durable message data
  • consumes daemon capability

必须保留的简单性

v1 只为 message.available 打通在线通知。不要把它设计成通用 event bus、workflow engine、插件系统或跨业务平台。

必须避免的模糊性

message.send 不再接 to_buddy 并由 daemon 猜目标。要发送就传明确 target_actor_address；要发现目标就查 contacts。

6. Daemon 先行实施顺序

P1-P5 都属于本次 new daemon upgrade 的 daemon 交付范围。phase 是执行拆分，不是允许交付过渡态。

本次任务包含

central daemon 独立进程、presence registry、contacts/reachability RPC、instance mailbox、message.available consumer、ActionGateway trigger。

本次任务不包含

不改造 message.contacts / message.send / message.list 的完整业务实现。daemon 只交付可被 message 消费的能力和契约。

P1

central daemon 独立进程骨架

新增 shared-root 级 lifecycle、socket、pid、log、status、ready probe。先能独立启动、查询、停止。

P2

presence registry 迁入 central daemon

instance daemon 只能通过 central daemon register/unregister/heartbeat；registry 由 central daemon 单点写入。

P3

contacts.list 与 reachability

提供 message.contacts 和 message.send 需要的查询能力，明确 online、registered_offline、never_registered。

P4

instance daemon mailbox

每个 instance daemon 暴露 mailbox endpoint；central daemon 将 event 投递到目标 mailbox。

P5

daemon-side message.available consumer 与 ActionGateway trigger

target instance daemon 消费 event，调度目标 buddy 读取消息。这里属于 daemon 能力，不实现 message 工具自身的 contacts/send/list 业务升级。

完成标准

最终交付必须走新 daemon 主路径：移除旧的 direct file append、to_buddy 模糊解析、ambiguous_online_actor 主路径和库级 daemon_presence 写 registry 的残留。不要保留新旧双轨兼容作为长期负担。

7. 当前 fea-inst 前置能力与待清除残留

actor_profile 已经完成关键前置条件；daemon 侧要直接替换成独立进程通讯层，不能把现有 helper 当成兼容层长期保留。

已经可复用

能力说明
RuntimeActorAddress已能表达 buddy_id + instance_id，并拒绝非 identity 字段。
actor_address projectiondaemon registration 可以消费 actor_profile 输出，不再自行拼身份。
reference-only event 方向已有 message.available 事件形态，可作为目标契约基础。

必须替换或清除

现状目标
daemon_presence.py 作为库 helper 直接写 registry。删除或收敛为 central daemon client；registry 只能由 central daemon 单点维护。
