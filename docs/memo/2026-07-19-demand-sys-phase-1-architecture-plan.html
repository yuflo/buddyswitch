四阶段边界

点击查看每阶段唯一结果。当前计划只实施 Phase 1。

BUILD NOW

Demand 自己成立

  • canonical state + atomic repository
  • check/index/get_many/ack
  • tree/dependency/lineage actions
  • actor tool + read-only CLI
EXIT

D→C 收敛可观测

  • one live C
  • terminal D absorbed into C
  • pending check = 0
  • Task records = 0
NOT BUILT NOW

Demand 变化获得 actor 注意

  • Demand-owned attention policy
  • generic Actor Input capability
  • daemon only transports/wakes
BOUNDARY

Domain 仍不依赖 daemon

  • runtime adapter composes both
  • fixed check prompt carries no truth
  • no Task involvement
NOT BUILT NOW

Actor 使用单 active Task 消费 Demand

  • actor calls both APIs separately
  • Task completion is evidence
  • actor explicitly reconciles Demand
FORBIDDEN

没有跨域自动联动

  • Demand never calls Task
  • Task never completes Demand
  • no shared transaction/callback
NOT BUILT NOW

真实 inbound 先形成 Demand

  • source-by-source direct cutover
  • same-source old Task ingress deleted
  • no dual write or fallback
FINAL TRUTH

Inbound → Demand → Actor → optional Task

  • controlled inbound only
  • direct TUI input remains outside intake
  • one write path per source
