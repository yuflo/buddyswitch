目标与非目标

本次只解决单 Task lifecycle 的唯一状态与 Progress Check 闭环。

Goal

目标

  • 受控 inbound 创建一个 durable、actor-owned Task。
  • 同一个 task_id 从 side 经 handoff 进入 parent，直至终态。
  • Task status 是 lifecycle 的唯一事实来源。
  • actor 通过 prompt-driven Progress Check 判断 close、continue、handoff 或 cancel。
  • 所有合法越迁由 Task Sys domain 集中定义和校验。
Non-goal

不进入本次范围

  • Relation schema redesign、task merge、dependency graph 或 multi-task coordination。
  • 将直接 Codex-TUI user input 重新纳入 Task Sys inbound。
  • 用程序规则自动判断完成、阻塞或替 actor close。
  • 恢复 checkpoint Task、checkpoint status 或 checkpoint_update。
  • 在通用 daemon 中加入 Task Sys 业务判断，或引入 workflow/rule engine。

冻结的 lifecycle contract

in_progress 只是分组，不能单独落地；下面五项是全部 concrete statuses。

in_progress.side_processing

Task 创建后的初始状态；side 独立处理。

in_progress.awaiting_parent

side 已判断需要 parent，等待 parent frame 成功提交。

in_progress.parent_processing

parent 已接收同一个 Task 并持续处理。

completed

actor 判断工作完成；终态。

canceled

合法取消；终态。

核心风险与注意事项

这些约束防止实现把简单 lifecycle 再次扩展成多套隐式状态。

State drift

不能保留第二套状态来源

processor、handoff record、result、event、frame 和 cleanup 只能作为 execution evidence，不能决定 lifecycle。若字段与 status 重复表达同一语义，应删除或改为由 status 投影。

Failure path

失败不自动制造 lifecycle status

parent 提交失败时保持 awaiting_parent 并记录 runtime failure；side/parent runtime failure 也只记录事实。恢复、重试和清理不能替 actor 判断完成。

Boundary

daemon 必须保持 product-neutral

Task Sys 决定 active Task、prompt 内容和 lifecycle action；daemon 只交付 trigger 与 prompt。不要把 Task 选择规则写进 generic handler。

Scope

Relation 只解耦，不在本次重做

移除 mandatory analysis/gating 即止。不要顺手引入 relation 新 schema、自动合并、waiting graph、objective anchor 或跨 Task 副作用。
