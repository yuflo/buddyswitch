方案二：不建设 contact 层，只建设一个 IM target resolver

这份 memo 更新了前一版表达：统一点不是新的联系人投影层，而是发送前唯一目标解析函数。message.contacts 只是列表视图，不能成为权威规则层。

新结论 少一层架构

不用新增权威联系人层。发送前只需要 resolve_im_send_target(...)。

唯一事实 identity first

actor / external 都先从 identity 模块解析，不再出现两套身份入口。

保留边界 daemon 只做 actor runtime

actor 在线、heartbeat、mailbox endpoint 留在 central daemon registry。

保留边界 session 只做 API 会话

external_session 只保存 auth key 和 cursor，不承载 reach 规则。

核心判断

preferred 更简单的架构是：target resolution 是唯一发送前权威；contact 只是读取视图。

当前问题不是缺一个 contact registry，而是 actor 发送入口把 target_identity_id 解释成 actor runtime row。把这个入口改成统一 target resolver，就能同时保持 identity 统一、daemon 边界清晰、external session 不被误用，并且删除 send path 对 actor 列表/row shape 的依赖。

目标流程

Sender input target_identity_id

actor 或 external 从自己的 send surface 发起消息，输入的是目标 identity id。

Identity module 解析静态身份

确认目标是合法 act-* 或 ext-*，并读取对应 profile。

→
Single resolver resolve_im_send_target

唯一发送前规则入口。它不返回 contact row，只返回可写入 IM 的目标 identity 或明确错误。

resolve_im_send_target( sender_identity, target_identity_id ) -> { ok, target_identity }
Actor branch identity exists + daemon online

如果目标是 actor，resolver 先确认 actor identity profile 存在，再调用 daemon.check_reachability(target_identity_id) 确认 online。

External branch identity exists + IM writable

如果目标是 external，resolver 确认 external identity profile 存在，并允许写入其 IM visible event；不模拟在线进程。

→
Message write send_im_message

resolver 通过后，写入统一 conversation、message、event、state。

Actor delivery actor target 才 wake actor

这是 target-side delivery，不回流污染 sender-side resolver。

External read external target 通过 read/ack 消费

external client 读取 visible event；是否及时读取不属于 sender reach。

概念删减

删掉 联系人层作为架构权威

不再把 contact 建成独立事实源或发送规则源。否则会引入新的状态漂移点。

  • 不新增权威联系人表
  • 不让发送路径依赖联系人行结构
  • 不让 external session 伪装 contact 状态
保留 message.contacts 作为视图

它可以列出可选目标，但不是规则权威。发送是否允许必须以 resolver 为准。

  • 用于发现目标
  • 可按 role / identity type 做过滤
  • 可以复用 identity / daemon 查询能力，但不能参与 send target 判断

send path 的减法

从发送路径删除 列表/row shape 依赖

发送给一个明确目标时，不再先拉在线 actor 列表，也不再遍历 actor rows。

  • _online_actor_rows() 不服务 message.send
  • list_online_actors() 不服务 send target 判断
  • actor_rows 不作为 resolver 输入
  • identity_for_current_send_target(actor_rows, ...) 被替换
发送路径保留 直接目标判断

发送路径只做明确目标的身份和可写入判断，不理解列表视图。

  • actor：get_actor_identity_profile(...) + check_reachability(...)
  • external：get_external_profile(...) + IM writable
  • 通过后只返回 target_identity

模块边界

Identity 拥有静态身份

actor / external 的 profile、type、display name 等静态身份事实唯一归这里。

Central daemon 拥有 actor runtime presence

只回答 actor 是否在线、mailbox endpoint 在哪里。它不认识 external user。

IM service 拥有 send target resolution

接收 target_identity_id，解析成可写入 IM 的目标 identity。

External session 拥有 API auth / cursor

只服务 external client 调用和事件读取位置，不定义谁可达。

Message write 拥有 durable IM state

conversation、message、event、message state 仍保持 identity-addressed。

Delivery 拥有 target-side handling

actor wake 与 external read/ack 是写入后的分支，不进入 resolver。

现状到目标

现在 actor send target 被解释成 actor runtime row

这导致 ext-* 在发送前就被拒绝，因为它不是 daemon 里的在线 actor。

ActorImClient.send -> _online_actor_rows() -> identity_for_current_send_target(actor_rows, target_identity_id) -> reject ext-*
目标 actor send target 被解释成 IM target identity

actor / external 都走同一个 resolver。差异只在 resolver 内部查什么事实。

ActorImClient.send -> resolve_im_send_target(sender_identity, target_identity_id) -> send_im_message(sender_identity, target_identity) -> post-write delivery

external 的“可达”怎么更简单

在 /api/im/* 这一层，external 不是在线进程，所以不要给它造 daemon-style online。它的发送前判断应简化为：identity 存在、type 是 external、IM policy 允许写入该 identity 的 visible event。后续客户端什么时候读取，是 external-side read/ack，不属于 sender reach。

  • actor target：identity 存在 + actor runtime online。
  • external target：identity 存在 + IM 可写入 external visible event。
  • channel adapter 的真实外部投递，仍在更外层处理，不进入本次 resolver。

验收标准

结构验收 少概念
  • 没有新的 contact 权威表。
  • 没有把 ext-* 写进 central daemon registry。
  • 没有让 external_session 承担 reach。
  • 只有一个发送前 resolver。
  • resolver 不接收 actor_rows。
行为验收 统一入口
  • message.send(target_identity_id=act-...) 走 resolver。
  • message.send(target_identity_id=ext-...) 走同一个 resolver。
  • message.contacts 不决定发送规则。
  • list_online_actors 不再参与发送目标判断。
  • actor delivery 与 external read/ack 仍在写入后分支。
