System / Flow Explainer

显式模块化单体，而不是万能插件 Kernel

这份 HTML 帮助 BuddySwitch 开发者审阅一个 Forward 目标：高频 Private 变化收进一个物理产品模块；应用只显式选择完整模块；基础宿主保持业务无关；只有 Role 使用自己窄而真实的扩展宿主。

一个物理 owner 模块级显式组合 Private 独立迭代 Role 专用发现 拒绝万能插件平台
核心判断：显式组合没有错，错的是组合粒度。 应用根可以知道 Demand、Task、Track；它不应知道 DemandTriageHandler、具体 Tool、route 或 Skill。新增一个完整产品模块只改一次应用根，模块内部变化不再穿透边界。

1 edit Whole product module

0 Private central lists

1 host Role extension surface

RoleHost 只发现经过评审的本地 RolePackage；不发现产品模块。

Target topology

一条显式产品装配路径，一条独立 Role 扩展路径

产品模块不是插件。应用根显式决定产品集合；基础宿主只接收自己拥有的类型。Role 是不同的高频扩展面，由专用 Host 按窄 schema 发现。

纵向装配module.py 返回命名、静态类型化的 assembly；Host contract 由接收方拥有。
横向协作模块之间直接调用对方 public/；不绕进 Kernel、Bus 或 service locator。
显式中心应用根保留一个低频产品模块列表；这是可审阅的产品真相，不是耦合缺陷。
Role 例外RoleHost 只扫描一个受信本地 Role 根，descriptor 错误或 ID 冲突在启动前失败。

Module anatomy

一个产品模块 = 小 Public + 大 Private + 本地装配 + 本地测试

物理聚合服务于高频 Private 迭代。架构只约束跨边界依赖和装配契约，不规定模块内部每一个文件夹。

Foundation

Daemon / Tool / Web / State

业务无关宿主能力；接受类型化注册，不选择产品集合。

Product module

Demand / Task / Track / Artifact

拥有状态、规则、适配器、Skill、资产和模块测试；由应用根显式选择。

Role package

market / dev / investor

拥有 AGENTS、Skills、脚本、模板和测试；由 RoleHost 校验发现。

Not a layer

Kernel / Bus / Container

不建立通用业务发现、语义事件总线、DI 容器或远程插件市场。

public/
只放真实跨模块消费者需要的 Commands、Queries、Types 与明确错误；没有消费者就不制造接口。
private/
Domain、State、Tool、Daemon handler、Web/CLI、Skill 执行代码和内部组织都属于高频自由区。
module.py
无副作用地组装命名、静态类型化的 host contributions；不扫描目录、不提供 lifecycle、不暴露 service locator。
state owner
模块显式声明 owner、schema version、storage identity 和唯一写路径；禁止从目录名推导持久化 namespace。
tests/
模块 Unit、Contract、Integration 与源码聚合；跨模块、Process、System 和全局 Architecture 仍留在 root tests。

One physical owner

删除模块目录时，其实现、assets 和模块测试一起退出，不留下散落副本。

Public only

跨模块只能 import 对方 public/；Public 依赖图不得循环。

Host-owned types

DaemonHandler、ToolRegistration、WebRoute 等类型由接收宿主拥有，模块只构造它们。

One explicit set

应用根拥有完整产品模块集合；这份低频真相明确存在，不用目录扫描隐藏。

Fail at startup

重复 Tool、route、command、模块 ID 或无效 assembly 必须阻止部分应用启动。

Local freedom

架构测试约束方向、owner 和 residue，不硬编码每个 Private 文件的内部布局。

Composition flow

显式选择模块，模块局部组装，宿主类型化接收

没有通用 loader。应用根可以认识模块名，但不能穿透模块 Private；宿主可以认识自己的 contract，但不能认识产品名。

1 · Module private implementation本模块实现 Domain、State、Tool、Daemon、Web/CLI 与 Skills。
2 · module.py assembly把本模块内部 pieces 组装成 host-owned、静态类型化字段；无 Any、无字符串 kind dispatch。
3 · Application composition root显式列出 (DEMAND, TASK, TRACK, ...)，校验重复并把 typed fields 交给宿主。
4 · Foundation hostsDaemon、Tool、Web/CLI 分别只处理自己拥有的 registration；不扫描或分支产品语义。
5 · Current observable behaviorTool schema/effects、Daemon recovery、Web/CLI 结果、Actor lifecycle 与 canonical state 保持。

Earned extension host

Role 是专用扩展面，不是产品模块，也不是万能 Plugin

Role 的 Private 内容与执行代码变化频繁，公开 package schema 变化不频繁。这种真实压力允许一个窄 Host；不允许借机抽象 PluginHost[Any]。

Forward migration

逐模块直接替换，不做全仓大爆炸，也不留双轨

原子性属于单个产品模块：一次切走 Demand 的全部 owner surface，并删除旧 Demand 路径。边界证明后，其他独立模块才获得真正并行。

Simplicity fence

没有 Product Module Scanner 没有 Event Bus 没有 DI Container 没有 requires/provides DSL 没有热插拔 没有兼容 alias / fallback 没有第二 Test Runner

Acceptance

验收变更局部性、显式性和真实产品效果

目录外观不是结果。必须同时证明 owner、依赖方向、组合语义、Role 失败行为、旧路径删除和现有消费者闭环。

Change locality

Private 只动一个根

新增或删除模块内 Tool、handler、route、Skill、test 只改 owning module，不改 app root。

Explicit product set

完整模块一次选择

新增产品模块只增加其目录并修改一次 composition root；没有目录自动激活。

Architecture

Host 业务无关

Foundation 无产品 import/token；composition 不 import module private；跨模块只走 Public。

Role extension

窄发现、失败关闭

有效 Role 不改中央列表；重复 ID、无效 schema 或缺失资产在 Actor 启动前失败。

Replacement

迁移模块只有一条路

没有 alias、fallback、双 Tool、双 handler、双 schema、双写或旧测试保护。

Product / Operations

消费者观察一致

Demand/Task/Goal、Tool、Daemon recovery、Web/CLI、Actor lifecycle 与 cleanup 仍精确。

机器验收清单

One test entry./buddyswitch-test
  1. Private-only 产品变更的实现、资产和 owning tests 位于一个模块根。
  2. 新增/删除模块内 handler、Tool、route 或 Skill 不修改 Application Composition Root。
  3. 新增完整产品模块需要一个新模块目录和一次显式 app-root 变更。
  4. Foundation 不 import 产品模块；composition 只 import modules.<name>.module。
  5. 跨模块 import 只进入 public/，Public dependency graph 无循环。
  6. 不存在扫描产品模块目录的 universal loader 或 Probe Module 自动激活行为。
  7. State owner、schema、storage identity 和 write path 显式且唯一，不从目录名推导。
  8. 有效 Role package 无需中央 Role list；无效/重复 Role fail closed。
  9. Co-located module tests 通过现有 ./buddyswitch-test focused 运行；无第二 runner。
  10. 迁移模块旧路径、旧注册、alias、fallback、双读写和兼容 tests 扫描为零。
  11. 受影响真实 Web/Actor/Daemon/Tool 消费者闭环通过；仅 catalog/registration 测试不足。

最终设计判断

BuddySwitch 的乐高化不来自“所有东西都自动发现”，而来自正确的物理 owner 和正确的组合粒度：Private 在模块内自由，产品集合在应用根显式，基础宿主业务无关，只有已经证明高频扩展压力的 Role 拥有专用发现机制。

Proposed Forward target
Artifact job：通过目标拓扑、当前代码证据、模块解剖、显式组合、Role 例外、逐模块迁移与机器验收，帮助团队审阅一套不复杂化、可直接 Forward 实施的 BuddySwitch 模块化单体架构。
