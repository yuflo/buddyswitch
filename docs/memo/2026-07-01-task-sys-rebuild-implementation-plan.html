目标和非目标

本方案按 rebuild 原则制定：不做旧行为兼容，不留下双轨解释，不把 runtime event 伪装成 task。

目标 1：统一 Task 本体

普通 inbound info 进入后由系统创建一个 actor-owned task。这个 task 覆盖从接收、side 处理、parent 转手、完成或失败的完整生命周期。

保留task_id 贯穿

目标 2：frame 降级为 runtime 输入

side_frame、parent_frame 只表示 task 的当前投递文本或 runtime envelope。它们不是 side task、parent task，也不应该进入 task 列表成为候选任务。

重定界frame 非领域对象

目标 3：actor ongoing task 一等可见

actor 需要能清楚看到自己正在进行中的 task，包括 parent/main thread 正在推进的 task。这个能力应由 Task Sys 清晰提供。

新增读视图不新增创建权

目标 4：turn_completed 不再建 task

turn completed 是 runtime event。它可以被记录到已有 task 的历史里，或被 daemon 用于 task lifecycle guard，但绝不能创建 app_server.turn_completed task。

删除checkpoint task

非目标：side 判断准确性

这轮不优化 side 是否应该移交 parent 的推理质量、prompt 边界、资源判断策略。只修正 Task Sys 基础语义和可观察性。

暂不做handoff policy

非目标：actor 创建 task

Task 创建仍然归系统 ingress。actor 可以读、推进、关闭已有 task，但不获得创建 Task Sys task 的工具能力。

不开放task create

目标模型

用一个 task record 表达生命周期。frame、processor、turn event 都是 task 的属性或历史，不是并列领域对象。

{
  "id": "task-im-message-created-...",
  "actor_target": {"actor_id": "...", "role_id": "pm"},
  "source": {"type": "im.message.created", "ref": {"message_id": "..."}},
  "inbound_context": {"message_id": "...", "conversation_id": "..."},
  "status": "side_processing | needs_parent | parent_processing | closed | runtime_failed | side_no_result | side_timed_out",
  "active_processor": "side | parent | null",
  "parent_handoff": {"params": {}, "submitted_turn_id": "..."},
  "close_result": {"processor": "side | parent", "summary": "..."},
  "failure_result": {"processor": "side", "stage": "...", "error": "..."},
  "events": [
    {"type": "created", "at": "..."},
    {"type": "side_frame_started", "at": "..."},
    {"type": "parent_requested", "at": "..."},
    {"type": "parent_turn_completed", "turn_id": "...", "at": "..."}
  ],
  "created_at": "...",
  "updated_at": "..."
}
概念目标定义不允许
Taskactor-owned inbound lifecycle，本体数据，持久化。把 checkout、turn completed、frame 投递都建成 task。
Frame从 task 当前状态生成的 runtime 输入文本。frame 作为 task 分类或 task record 来源。
Processor当前执行者：side 或 parent。processor 被命名成独立任务类型。
Turn event运行时事实，可追加到已有 task history。成为 app_server.turn_completed task。
Context保留 orientation，但不再是唯一 task 读入口。让 actor 从 candidate_tasks 猜 ongoing task。
删除不是隐藏：这些名字和测试契约要从 actor-facing tool、runtime frame、role guidance、context source text、测试断言里消失。只有 app_server.turn_completed 作为 daemon trigger 类型可保留。

目标 API 和工具面

系统创建 task，actor 读和推进 task。这里不开放 actor create，也不保留 checkpoint_update。

层目标接口动作说明
Launcher ingress ingest_user_input, ingest_im_message, ingest_track_comment create 统一调用一个 inbound task 创建路径。删除 initial_processor 变体。
Domain read list_tasks, active_tasks_for_actor, get_task read 返回 actor-owned task 和内嵌 lifecycle events。
Actor tool read task_sys.list, task_sys.get read 让 actor 明确看到 ongoing/active/recoverable task。替代靠 context 泛化列表猜测。
Actor tool write task_sys.close, task_sys.need_parent write 推进同一个 task 的生命周期。need_parent 是转手，不是新建。
Runtime observer record_turn_completed_for_task event main turn completed 只追加到已有 task history。找不到 task 绑定则忽略或记录 daemon runtime event，不进入 Task Sys task list。

实施阶段

每个阶段都要前进式替换，不保留旧路径。阶段可以分 PR，但不允许最终形态双轨。

1

先写目标契约测试

  • 定义 Task 本体：one inbound -> one actor-owned task。
  • 定义 active/ongoing task 视图。
  • 定义 turn_completed 不创建 task。
  • 定义 actor-facing tool 集合不包含 checkpoint_update。
预期：新测试在当前代码上失败，失败点直接对应 rebuild 目标。
2

重建 Task Sys domain

  • 删除 INITIAL_PROCESSORS、checkpoint status、checkpoint_metadata。
  • 保留并收紧 side -> needs_parent -> parent_processing -> closed 状态链。
  • 新增内嵌 events 作为 task lifecycle history。
  • 删除 orphan domain/tasks.py 及 task-specific compatibility 名字。
预期：Task record 自身足够表达生命周期，frame 不再成为领域对象。
3

重写 runtime ingress 和 checkout

  • 普通 inbound 统一走 task create -> start_side。
  • 删除 ingest_turn_completed。
  • turn completed handler 找已有 task binding，追加 event；找不到则忽略。
  • 如需提醒 parent，提交引用已有 task_id 的 continuation frame，不落 task record。
预期：main turn 结束不会污染 task list。
4

重建 actor tool 和指导

  • task_sys tool 改为 list/get/close/need_parent。
  • role AGENTS 和 task-management skill 移除 checkpoint 教学。
  • context summary 改成 active_tasks 或明确指向 task_sys.list/get。
预期：actor 能清楚看见 ongoing task，不需要靠 context 反推。
5

更新 UI/daemon projection 和全量测试

  • daemon/web task_sys projection 改用新 active/recoverable 语义。
  • 删除 checkpoint 相关测试，按目标模型补充端到端测试。
  • 跑 focused tests，再跑相关 broader tests。
预期：所有入口和可观察面使用同一套 Task 本体语言。
