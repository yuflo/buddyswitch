Communication / IM Identity Cutover

这个 HTML 专门审核 B：在 Task A 已建立唯一 identity owner 的前提下， 把 runtime、daemon、IM、mailbox、Track、Artifact、Comment、Web 等通信相关链路 切到只引用 identity，删除 ActorAddress 和 IM participant 私有身份 schema。

依赖 A 不重新定义 identity，只消费 A 的 identity profile contract。
删除通信旧形状 actor_address 与 IM participant 身份 schema 清零。
不开放 external actor -> external 主动发送仍不是本任务能力。

审核结论

B 应独立成通信 cutover 任务说明。它的核心不是设计 identity profile， 而是让所有通信路径消费 identity，删除 actor-only 地址和 IM 私有 participant 身份。

1. 任务目标

B 的目标是通信链路引用 identity，而不是在通信模块里再维护 actor/external 静态身份资料。

Objective

runtime / daemon cutover

注册、心跳、可达性、signal、wake、mailbox 都用 identity 表达 source/target。

target_actor_address -> target_identity

IM participant 删除

IM 不再使用 kind + actor_address / external_id 表达身份。

sender_identity / target_identity / viewer_identity

product surface 清理

Track、Artifact、Comment、Context、Web 只传 identity 或 identity_id。

active_actor / actor_address -> identity

2. 对 Task A 的依赖

B 的前提是 A 已经定义唯一静态身份 owner。B 不允许补一套临时 identity schema。

Dependency
A 提供 B 如何使用 B 禁止做什么
IdentityRef 所有 source/target/viewer 都用同一 payload。 不在 IM/daemon/runtime 内重新定义 kind 或 actor_id + role_id。
ActorIdentityProfile 需要 actor 静态资料时查 identity profile。 不在 daemon registry、web row、IM contact row 复制 role/label 静态资料。
ExternalIdentityProfile external connection / channel 只保存连接事实。 不再用 IM participant 的 external_id 作为身份 schema。

3. 当前通信问题

当前 actor -> external 卡点来自通信入口把 target 解释成 reachable actor，而不是全局 identity。

Current Path
当前路径 问题 B 的替换方向
actor send target target_identity_id 先被 actor runtime 解析成 reachable actor。 先做 identity validation，再按规则判断是否允许 actor-directed delivery。
daemon registry 用 actor_address 作为可达性和投递 key。 registry 用 identity 作为 key，只保存 delivery state。
daemon signal / mailbox source_actor_address / target_actor_address 只能表达 actor-only。 source_identity / target_identity。
IM participant {"kind":"actor","actor_address":...} 和 {"kind":"external","external_id":...} 是 IM 私有身份 schema。 IM service/repo 参数直接改成 identity。
product surfaces Track、Artifact、Comment、Context、Web 继续传播 actor 静态结构。 只传播 identity / identity_id；需要静态资料时查 A。

4. 目标通信流程

B 完成后，通信链路只搬运 identity 和领域事实，不再搬运 actor/external 静态身份结构。

Target Flow
Caller 提交 target identity id 或 reply_to。
IM Product 使用 sender/target/viewer identity 建 message/event/state。
Delivery Resolver 按 identity type 和当前规则判断可投递性。
Daemon / Channel actor identity 查 online endpoint；external channel 后续单独补。
Product Surfaces 所有通知/可见性/上下文只引用 identity。

IM service API

send_im_message( sender_identity=IdentityRef(...), target_identity=IdentityRef(...) | None, reply_to=... ) read_im_events(viewer_identity=IdentityRef(...)) get_im_direct_conversation(viewer_identity=..., target_identity=...)

Daemon delivery state

{ "identity": {"id": "act-...", "type": "actor"}, "endpoint": {...}, "heartbeat": {...}, "status": "online", "last_seen_at": "..." }

6. 不在 B 中开放

B 清理通信底座，不扩大 actor/external 产品通信能力。

Non-goals

external 主动发送仍不开放

  • message.send(target_identity_id="ext-...") 不作为可用能力交付。
  • iMessage / external channel 主动发出 route 不在 B 内补齐。
  • external contacts 是否进入 actor contacts 视图不在 B 内决定。

identity 静态资料不在 B 设计

  • B 不定义 ActorIdentityProfile 字段。
  • B 不维护 role label / display name / created_at。
  • B 缺静态资料时查 A 的 identity owner，不在本地复制。

7. B 的验收标准

验收重点是通信路径无旧身份 schema 残留，且现有行为不偷变。

Acceptance

行为验收

  1. actor -> actor message 主路径仍创建 durable IM message、event、state。
  2. daemon 能按 actor identity 查 online endpoint 并提交 wake/mailbox delivery。
  3. external -> actor -> reply_to external 现有回路仍通过。
  4. actor -> external 主动发送仍被拒绝，且不创建 IM message/conversation/event/state。
  5. Track / Artifact / Comment / Context / Web 可见性和通知仍能基于 identity 工作。

残留验收
