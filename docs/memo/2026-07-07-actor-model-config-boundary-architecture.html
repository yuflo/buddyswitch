Actor Model Config Boundary Architecture

This HTML helps the user inspect where BuddySwitch should apply actor-local parent and side model settings by separating configuration ownership from Codex RPC primitives and runtime orchestration.

Single config source Parent actor boundary Side actor boundary No dual-track Daemon is not owner Attach TUI out of scope for v1

Locked Decision

Do not embed model hot-loading in daemon handlers, raw Codex RPC, or low-level submit/lifecycle helpers.

Put policy in one actor-aware parent wrapper and one actor-aware side wrapper. The lower layers execute already-resolved intent.

V1 covers BuddySwitch-controlled inputs only. Attach TUI direct input bypasses BuddySwitch boundaries and is intentionally excluded.

System Boundary Map

Use the buttons to highlight ownership. The diagram intentionally keeps app_server.py, submit_turn.py, and side_thread_lifecycle.py out of actor config policy.

Parent Hot Reload

1

Reach actor parent boundary

Before any BuddySwitch-controlled parent turn is submitted, route through parent_thread_submit.py.

2

Apply thread setting

Call thread/settings/update with model and effort, then wait for thread/settings/updated.

3

Submit the turn

Delegate to submit_turn.py after settings are reconciled. Already running model calls are not changed.

parent_thread_submit.py: config = actor_model_config.parent(instance_json) app_server.thread_settings_update(thread_id, config) submit_turn.submit_turn(thread_id, text)

Side Creation Reload

1

Reach actor side boundary

Any automatic or manual side creation flows through actor_side_thread.py before lifecycle execution.

2

Resolve side config

Explicit request values win. Otherwise read model-config.json side defaults.

3

Fork with creation params

Pass resolved model and model_reasoning_effort into side_thread_lifecycle.start_side_thread(...). Existing side threads are not mutated.

actor_side_thread.py: config = actor_model_config.side(instance_json) options = merge_explicit_overrides(config, request) side_thread_lifecycle.start_side_thread(..., model=options.model, model_reasoning_effort=options.effort)

Config Contract

Instance-local config is the runtime authority. Role defaults may seed this file at instance creation, but do not overwrite it later.

instances/<actor-id>/model-config.json { "schema_version": 1, "parent": { "model": "gpt-5.4", "effort": "high" }, "side": { "model": "gpt-5.4-mini", "effort": "medium" } }
Do not write this into instance.json. That file is active runtime state and side lease storage.

Priority Rules

1

Explicit request override

Manual side creation with --model or --effort wins for that new side thread only.

2

Actor instance config

Use model-config.json for parent and side defaults.

3

Codex default behavior

If a field is missing, omit it from the Codex request and let Codex inherit or use its current default.

Ownership Rules

actor_model_config.py

  • Owns schema, validation, read, and seed defaults.
  • Knows actor instance paths.
  • Does not call Codex RPC.

app_server.py

  • Owns JSON-RPC framing and primitive methods.
  • Does not read actor files.
  • Does not decide parent versus side policy.

parent_thread_submit.py

  • Owns actor-aware parent reconcile before controlled parent turns.
  • Uses thread/settings/update.
  • Delegates actual start/steer to submit_turn.py.

actor_side_thread.py

  • Owns actor-aware side config resolve.
  • Merges explicit side creation overrides with instance defaults.
  • Delegates lifecycle execution to side_thread_lifecycle.py.

submit_turn.py

  • Owns parent thread idle/active start-or-steer mechanics.
  • Does not read actor config.
  • Does not call thread/settings/update.

side_thread_lifecycle.py

  • Owns side-thread fork, inject, start, send, cleanup, and registry lease execution.
  • Does not read model-config.json.
  • Uses thread/fork model/config params.

Daemon service

  • Observes triggers and executes runtime instructions.
  • Calls actor-aware parent and side boundaries indirectly through controlled runtime paths.
  • Does not own model policy or handler-specific branches.

Task Sys

  • Owns task frames and instruction generation.
  • Does not encode model selection policy.
  • Benefits from actor-aware parent and side boundaries automatically.

Rebuild Path

This is the single forward path. Do not keep legacy direct lifecycle policy reads beside the new wrappers.

Short Term

  • Add actor_model_config.py, parent_thread_submit.py, and actor_side_thread.py.
  • Move controlled parent submits to parent_thread_submit.py.
  • Move controlled side starts to actor_side_thread.py.

Keep Narrow

  • Keep submit_turn.py and side_thread_lifecycle.py as execution helpers.
  • No daemon-by-scenario model branches.
  • No alternate side config read path in lifecycle.

Later Cleanup

  • Rename or narrow instance_json lifecycle usage toward registry storage semantics.
  • Split registry persistence from lifecycle only when it becomes a real bottleneck.
  • Attach TUI support remains a separate future design, not a hidden v1 side path.

Failure Modes And Guardrails

Risk Handling Why
Invalid model-config.json Fail explicit config commands; runtime reconcile reports structured warning and falls back to omitted fields only if policy chooses soft mode. Bad config should be visible, not silently mutated into wrong model state.
Parent turn already running Apply settings for subsequent turns only. Do not claim current request changed. Codex settings update is thread-local future-turn behavior.
Attach TUI bypasses BuddySwitch submit Declare unsupported for v1. Users who need actor model-config behavior should use BuddySwitch-controlled CLI/Web/IM/Track paths. Supporting TUI direct input requires a separate background reconcile mechanism and would add a third trigger model.
Side config changes while side is active Do not mutate existing side. actor_side_thread.py applies the latest config only when a new side is created. Side model policy is creation-time fork policy.
Policy leaking into execution helpers Keep app_server.py, submit_turn.py, and side_thread_lifecycle.py free of model-config file reads. Preserves one clear policy boundary and prevents hidden file I/O inside primitive execution paths.
