Actor Environment Build Pipeline

这份 HTML 帮助 reviewer 在实施前确认 Actor Environment Build 的目标、唯一 owner、固定 SOP、失败原子性、无 Git 环境边界、前向切换策略与验证门禁，避免把 worktree 替换成另一组散点脚本。

Recommended decision 建立一条 HostControl 独占调用的 Actor Environment Build SOP。

CLI 与 WebUI 继续在 HostControl.start(role) 汇合；HostControl 在服务启动前只调用一次 ActorEnvironmentBuilder.build(spec)。Builder 通过 allowlist copy 物化无 Git env，完成验证后原子发布。

01

Current state: one entry, scattered build

CLI 与 WebUI 的创建入口已经共享 HostControl；真正的结构问题位于共享入口之下：filesystem build、Git lifecycle、role customization、project projection 与 private surface 分散在多个 shell helper 中。

当前 bottleneck 不是“CLI 与 Web 各自 build”。

两者已在 HostControl 汇合。问题是 HostControl 下方没有一个完整、可命名、可独立验证的 build owner，导致 start 流程知道过多 workspace 细节。

02

Target architecture: one operation, one builder

上层保留已经正确的共享 HostControl；下层新增唯一的 filesystem materialization owner。Build 是 Actor Start 的内部阶段，不成为新的 CLI 命令或 Web API。

Builder owns

Filesystem environment

  • Shared project environment seed / validation
  • Actor staging root and instance filesystem roots
  • Allowlisted runtime file copy
  • Base Codex home/config/auth surface
  • Role AGENTS and runtime skills
  • Private surface and projects/app projection
  • Shape validation, staging cleanup, atomic publish
HostControl owns

Actor Start application flow

  • Role and Codex runtime validation
  • Actor id allocation and lifecycle lock
  • Single builder invocation
  • Instance record and capability activation
  • Broker, MCP, browser registration, app-server and daemon
  • Unified result and failure cleanup
Builder never owns

Runtime or transport behavior

  • CLI parsing or output rendering
  • HTTP DTOs, queueing or operation polling
  • App-server, broker or daemon processes
  • Thread bootstrap or retry policy
  • Git checkout, HEAD, branch, status or sync
  • Generic workflow, plugin, hook or pipeline registry
  • Legacy workspace migration or repair
关键边界：Build 成功仅代表 env 完整可运行；Actor Start 成功还要求 runtime services 启动完成。

这让 filesystem 原子性与 runtime lifecycle 分开验证，同时避免 Builder 吞入 HostControl 的业务责任。

03

Basic Build SOP

管线是固定顺序的具体过程，不是可配置 workflow engine。每一步都有前置条件、唯一动作、可观察输出和明确失败状态；正式 env 在第 10 步之前不可见。

Resolve

Construct BuildSpec

由 HostControl 提供已经校验的 repo_root、shared_root、actor_id、role_id、source Codex home 与目标 instance root。Builder 不读取隐式当前目录来猜测语义。

OUTPUT
one immutable BuildSpec
Preflight

Validate boundaries

校验 source 文件完整、role assets 可解析、目标都位于 shared root、root 不是 symlink、正式 actor workspace 尚不存在。任何失败发生在写入前。

OUTPUT
validated paths
zero mutation
Shared env

Ensure project environment

首次初始化时将 source projects/app copy 到 project staging 并原子发布。已存在时只验证为有效 env，不覆盖、不刷新、不从 source 同步。

OUTPUT
stable shared project env
Stage

Create actor staging root

在 actor instance root 的安全父目录内创建唯一临时目录。所有后续 copy 与 customization 都只写 staging，正式 workspace 仍不存在。

OUTPUT
private staging root
Materialize

Create instance filesystem roots

创建 workspace、home、codex-home、xdg-config、tmp 与 private 等 build-owned roots；安装 base config 和共享 auth surface。runtime PID/socket 状态不在此阶段创建。

OUTPUT
complete root skeleton
Materialize

Copy runtime surface

按代码内显式 RUNTIME_COPY_PATHS 复制 runtime kernel、env tools、manifest、profiles 与 contracts。禁止复制 repo root，因而 source .git 没有进入输出的路径。

OUTPUT
allowlisted runtime files
Customize

Apply role surface

安装 role AGENTS，并直接复用 install_runtime_skills() 物化 manifest 指定 skills。没有第二份 skill copy 逻辑，也没有 role-specific build branch。

OUTPUT
role-ready workspace
Attach

Attach env surfaces

将 staging workspace 的 projects/app 指向 shared project environment，确认 private root 为真实 instance-local directory。只建立当前产品契约需要的 projection。

OUTPUT
project + private boundaries
Prove

Validate final shape

断言 required surface 存在、forbidden source surface 缺失、project projection 精确、private 可写、正式 env roots 不携带 .git，且所有 target 仍在 shared root 内。

OUTPUT
validated BuildResult draft
Publish

Atomic publish and report

将完整 staging 原子发布为正式 actor environment，返回 typed BuildResult。只有此步骤成功后，HostControl 才能写 instance record 并启动 runtime services。

OUTPUT
complete env or no env
Stable extension point

增加 runtime 文件只有一条维护路径

修改 RUNTIME_COPY_PATHS，更新 shape assertion，并运行 focused build tests。无需理解 sparse checkout 或给多个入口补分支。

Rejected abstraction

不把 SOP 做成 pipeline framework

没有 YAML、step registry、plugin hooks、动态 DAG、build cache、bundle version 或双向同步。步骤顺序由一个顶层函数清楚表达。

Input invariant

Builder receives explicit facts

不读取 UI request、不解析 CLI、不从 cwd 猜 repo、不生成 actor id、不自行获取 lifecycle lock。

Output invariant

Complete env or absent env

成功返回的所有 path 已存在并通过 shape validation；失败时正式 actor workspace 不存在。

Integration invariant

Services wait for BuildResult

HostControl 不得在 build success 之前创建 broker、app-server、thread 或 daemon。

05

Failure model: fail closed, clean staging

Build 稳定性的核心不是更多 fallback，而是每个失败点都不会发布半成品、不会启动下游服务、不会覆盖 shared project content。

Preflight
Source 或路径边界无效

零写入退出；HostControl 返回同一个 start failure。CLI 与 Web 只做各自 transport mapping。

Project seed
首次 project copy 失败

删除 project staging；正式 project env 保持不存在。不得留下部分 projects/app。

Actor copy
runtime copy 或 role install 失败

删除 actor staging；正式 workspace 不存在；runtime services 未启动。

Validation
required / forbidden shape 不满足

视为 build failure，不尝试 repair、fallback 或切回 worktree；删除 staging。

Publish
atomic rename 失败

清理 staging；正式目标不得被递归覆盖。HostControl 停止 start 流程。

Service start
build 成功后 runtime 启动失败

由 Actor Start failure cleanup 处理并记录 inactive failure；Builder 不承担进程 rollback。

明确禁止：用 fallback 掩盖错误。

不允许 copy 失败后回退 worktree，不允许 project env 缺失时从旧 execution workspace 恢复，不允许 shape validation 失败后“尽力继续”启动服务。

06

Forward-only cutover

新 build contract 只有一条 active path。旧 worktree env 不自动转换、不修复、不继续运行；它们必须在切换前由操作者处理需要保留的内容并 reset。

Delete completely

历史 build 机制与语汇

  • git worktree add/remove/list/prune actor-env 路径
  • sparse checkout path configuration and validation
  • HEAD sync, dirty worktree checks and output staging around Git rebuild
  • runtime workspace commit/rebase/push guardrail hooks
  • registered-worktree cleanup strategies and tests
  • worktree repair, migration, compatibility wrapper and fallback branches
  • 生产函数名、错误文案与测试名中的 execution/project worktree 残留
Keep as current product contracts

与 Git 无关的有效边界

  • CLI 与 WebUI 共享 HostControl.start
  • Web lifecycle operation queue 只包装 HostControl
  • shared project source across actors
  • actor-local private workspace
  • role AGENTS and manifest-selected runtime skills
  • Codex runtime provenance validation
  • global runtime lifecycle lock
  • broker / app-server / daemon service ownership
Existing environment rule

不做自动迁移

当前 env 若不满足 Git-free shape，start/resume 直接拒绝。需要保留的 project content 由操作者在升级前显式导出；随后执行一次受确认的 env reset，再由新 builder 创建唯一新形态。

Current invariant

验证的是 env shape，不是历史版本

Builder 只检查当前 required / forbidden shape 与根目录边界，不维护 legacy version table、migration marker 或旧格式识别器。

08

Verification architecture

验证从一个明确 claim 开始：根据实施时的真实 diff 与 live references 发现 exact test 和 direct boundaries，证明当前 claim 后立即停止。资源 tier 是成本与边界分类，不是每轮必跑清单。

Start Name one exact claim
Discover Current diff + live references
Stop rule Exact + direct proof is enough
Reuse Identity-valid evidence survives review
Final Frozen candidate or explicit acceptance only
Dynamic target discovery

优先选择本次新增或修改的 exact tests，再用 rg 追踪 changed public symbols、commands、contracts、fixtures 与 direct callers。没有命中不是成功：若 ownership 或 shared boundary 仍不清楚，明确记录 uncertainty 并进入 MILESTONE，而不是用 broad suite 掩盖缺少直接证据。

Evidence identity

一次 clean proof 可以被安全复用

记录 repo root、HEAD、tracked patch identity、全部 non-ignored untracked files、canonical command、material environment、exit/result/duration、cleanup residual、proved claim、valid-for 与 residual risk。

Invalidation

失败信号优先于历史通过

相关 source/test/fixture/contract 或 runner/environment 改变会使对应证据失效。Failure、flake、timeout 或 cleanup residue 必须先诊断；不得 blind rerun 到绿色后隐藏信号。

Positive proof

完整 env 可启动

Required runtime files、role skills、private、project projection、Codex home 与 services 均通过真实主路径。

Negative proof

错误不能漏过去

缺 source、越界 path、copy 失败、shape invalid、已有 Git root 都在 publish/service start 前失败。

Residue proof

旧路径真正消失

不是跳过旧函数，而是删除生产引用、测试 fixture、cleanup strategy、文案和双轨行为。
