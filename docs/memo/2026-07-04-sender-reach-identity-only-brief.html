Sender Reach / Identity-Only · 2026-07-04

1-5 只靠 Identity 工作的 sender reach 设计

核心判断 1-5 是 sender 视角 reach 从 message.send 到 Central IM message 写入，都应只依赖 sender identity、target identity、content、reply_to。
当前问题 target_role_id + wake_actor 这两个参数把 target 自己的 actor 处理细节带进 sender reach 和 message 写入接口。
第一阶段目标 做减法，不做新路由 先让 1-5 identity-only；actor 处理链路继续存在，但不嵌在 1-5 的收发接口里。

1. 边界定义

本 memo 只看 1-5

1-5 是 sender 发起 message 的 reach 过程：入口、target 解析、reach 判断、调用 message service、写入 Central IM message。

这里的 reach 是 sender 视角：sender 只应该知道目标是谁，以及这个目标能不能作为本次收发目标。

不把 6-8 拉进来

6-8 是 target actor 收到 message 后怎么被唤起、怎么从 mailbox/local trigger 继续处理。

本阶段不设计 external outbound channel，不新增 delivery queue，不推翻 daemon/mailbox。

2. 当前 1-5 现状

1
Tool schema 把收发目标写成 actor-directed
message.send 的说明是 “new actor-directed message”，target_identity_id 描述为 target actor identity id。
2
ActorImClient 读取 target_identity_id
有 target_identity_id 时进入 _send_target_identity(...)，否则只有 reply_to 才走既有会话回复。
3
target resolver 只认 actor reachable rows
ext-* 直接拒绝；act-* 通过 daemon online actor rows 解析，并返回 identity + role_id。
4
send 调用携带 target 的处理参数
ActorImClient.send 调 send_im_message(... target_role_id=..., wake_actor=...)。这一步开始把 target actor 处理细节带入 1-5。
5
send_im_message 写入 message 时顺手 wake actor
函数前半段已经能用 identity 写 conversation/message/state/event，但后半段检查 target_role_id 并构造 wake payload。

4. 目标形态：1-5 只需要 identity

1
Tool 入口只表达 target identity
target_identity_id 表示目标 identity id，不携带 target role、endpoint、mailbox 或 wake 信息。
2
Sender 解析 target identity
sender 侧只把输入规范化成 {"id": "...", "type": "actor|external"}，并拒绝 self-send / 空内容等 sender 侧错误。
3
Reach 判断只返回可发送目标 identity
这一阶段可以暂时继续把未接入 reach 的 external 判为不可收发，但这只能是 reach policy 的结果。一旦 reach 通过，返回结果只能是 target_identity，不能返回 role_id 作为 1-5 的必要输入。
4
ActorImClient 只调用 identity-shaped message service
调用形态收束为 send_im_message(sender_identity, to, content, reply_to)。
5
Central IM 写入只靠 identity 完成
conversation/message/state/event 的写入只依赖 sender_identity、target_identity、content、reply_to。不接收 target_role_id，不接收 wake_actor。

actor -> actor 和 actor -> ext-user 在 1-5 的目标接口形态相同：sender_identity -> target_identity。如果 actor -> ext-user 仍失败，失败点必须在 reach policy；不能再由 target_role_id、wake_actor 或 actor-only service signature 决定。

8. 不做的事

  • 不新增 generic delivery engine。
  • 不新增 external outbound channel 设计。
  • 不把 external 伪装成 actor runtime contact。
  • 不保留 send_im_message 的新旧双签名。
  • 不让 target_role_id 继续作为 sender reach 的必要输入。

10. 完成判断标准

  • send_im_message 签名不包含 target_role_id 或 wake_actor。
  • ActorImClient.send 调用 send_im_message 时只传 sender identity、target identity、content、reply_to。
  • target resolver 成功结果只给 target_identity；不把 role_id 作为 1-5 的必要输出。
  • Central IM conversation/message/state/event 仍然只按 identity 写入。
  • actor -> actor 收发仍能写入 message。
  • actor -> external 收发若仍拒绝，必须是 reach policy 拒绝，而不是 service 入参缺 actor role/wake。
  • actor wake / mailbox / local trigger 的测试留在 6-8，不作为 1-5 写入接口的参数或断言。
