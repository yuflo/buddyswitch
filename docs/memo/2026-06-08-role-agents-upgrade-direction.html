Actor Role 启动模板升级方向

目标：把 tools/launcher/assets/roles/*/AGENTS.md 从通用 runtime 提示，升级为短、准、可执行的 role bootstrap 文件。

核心判断

AGENTS.md 只做启动边界

role lock、第一步、状态边界、最终汇报。不要变成 workflow manual。

从 profile + contract 提炼

每条新增内容都应能追溯到 env-profiles、framework/contracts 或 manifest。

测试升级暂不处理

本轮只定义 role AGENTS 内容方向，不改测试策略。

抽取规则

  • Always-on：每个该 role turn 开始前都该知道。
  • Action-shaping：能防止错误第一步、错误权限假设、错误 durable state 处理。
  • Non-procedural：不复制 skill steps、tool schema、payload、artifact 模板。

建议结构

# BuddySwitch Runtime Workspace

This workspace is launcher-owned, runtime-only, and locked to the `<role>` role.
AGENTS.md is bootstrap guidance only and not the permission source.

## Bootstrap Rules
- shared runtime boundary
- context summary when runtime context is needed
- env tools for durable runtime state
- Buddybox/private files vs product-readable artifacts
- artifact full-body truth rule
- search/browser route
- broker rejection rule

## Role Entry
- 1-4 role-specific always-on rules

## Output Rule
- role-specific durable result, evidence, blocker, next action

Role 升级清单

Role 升级方向 建议加入内容 不要放进 AGENTS
design 从“通用 runtime 边界”升级为“设计输出入口”。
  • Shape UI/UX direction into durable design outputs.
  • 围绕显式 task_id / track_id；涉及 shared material/proof 时先 track__open。
  • 跨角色可读设计输出走 artifact / track material / proof。
  • prototype/export 可在 Buddybox；产品可读必须 artifact。
  • 若项目有 DESIGN.md 或 design-system artifact，优先遵守，不临时发明视觉系统。
 设计方法论、UI taste 细则、Figma workflow、artifact body 模板、raw output path。
dev 从“可编辑角色”升级为“受 runtime source workspace 约束的实现入口”。
  • Implement approved source scope and persist implementation evidence.
  • source write authority 来自 runtime profile/context，不来自 AGENTS。
  • 有 artifact id / upstream material 时，先读 track__open 和 full artifact__get body。
  • UI implementation 遵守现有组件、tokens、DESIGN.md 或 design artifact。
  • 最终输出包含 changed files、verification、durable report、risk。
 硬编码 projects/app、具体 build/test 命令、debug workflow、review workflow、payload schema。
pm 保留 PM ownership，并把入口更明确地指向 scope/decision/track lifecycle。
  • Own direction, scope, requirements, acceptance criteria, decisions, proof iteration.
  • 变更 shared track 前先读当前 shared state。
  • PM-only comment resolution 只在 runtime tool 授权时执行。
  • 最终输出说明 written durable objects、blocker、next owner/action。
 完整 PRD 模板、决策长格式、track 操作 recipe、跨角色 workflow 编排。
market 强化 evidence-first 和 browser/search 入口。
  • Start discovery through BuddySwitch search/browser tools.
  • Evidence is target-scoped and must not be fabricated.
  • market deliverables 先 artifact draft，需要共享再 publish to track。
  • 最终输出包含 artifacts、Buddybox files、evidence status、blockers。
 搜索 query 模板库、市场研究方法论长文、证据评分细则、浏览器操作步骤。
test 强化 verification scope 和 read-only source 边界。
  • Keep verification scope explicit.
  • Read shared materials via track + full artifact body before judging.
  • Do not edit source when active profile is read-only.
  • Persist pass/fail/blocked evidence through durable report/proof when needed。
  • 最终输出包含 scope、pass/fail/blocked、evidence、remaining risk。
 测试策略重构、具体测试命令清单、CI 规则、自动化测试设计方案。

统一不放

  • 不放 tool catalog / payload schema / JSON 示例。
  • 不放 raw runtime storage paths，避免诱导直接编辑。
  • 不复制 framework/contracts/*.md 完整内容。
  • 不复制 skill steps、examples、counterexamples。
  • 不把 AGENTS 写成权限源；权限仍由 profile、broker、runtime tools 执行。

落地顺序

  1. 先统一 5 个 AGENTS 的 section 结构。
  2. 给每个 role 加精简 Role Entry。
  3. 保留现有 runtime safety 规则。
  4. 不改测试；不同步旧 actor instance，除非明确需要 runtime 现场刷新。
