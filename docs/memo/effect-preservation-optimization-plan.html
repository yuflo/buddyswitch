二、逐项改造后评估

改造 动作 覆盖效果 可能效果损失 优化或权衡 验证门槛 风险
C01重写 description，去掉过窄的 through Codex CLI，加入 probe-only, simulated-user, feature memo, target behavior, existing evidence, claim downgrade。E01, E02, E08, E14触发过宽会让普通测试请求误用；触发过窄会漏掉 Desktop/browser/live/audit 场景。保留 BuddySwitch 和 simulated-user 作为强边界，不把通用测试、普通 CI、代码修复写进 trigger。用 8 个 prompt fixtures 做人工/子代理触发审核：memo run、plan only、target-only、audit evidence、ordinary unit-test request、bugfix request、browser profile request、non-BuddySwitch request。medium
C02把 SKILL.md 收成执行骨架：Purpose、Non-negotiables、SOP、completion criteria、reference routing。E02-E15如果只压缩不补 completion criteria，agent 可能更早宣布完成。每个 SOP step 加 checkable completion criterion，例如 effects extracted、strategy recorded、checkpoint recorded、summary validator clean。静态 diff 检查：15 个效果至少有一个主文件或 reference 位置承接；SOP 每步都有 done 条件。low
C03把 minimum input、defaults、checkpoint examples、pairings 的重复内容单一来源化到 references/invocation-and-pairing.md。E03, E06, E08如果 SOP 没有强制先读 invocation reference，默认继续和低输入行为会变弱。主文件只保留一句硬规则：do the thinking, one correction checkpoint, continue unless risk confirmation。SOP step 1 必须读 invocation reference 来定 mode/defaults/checkpoint。Design prompt 和 Run prompt 输出必须都包含 inferred defaults 和一个 checkpoint；Run 且无风险时不得等待二次批准。medium
C04保留 probe-only boundary 和 risk confirmation 列表在主文件，不下沉。E02, E07, E12, E13无。这里是主动不改，避免把安全/授权边界降到 reference 层。可只删重复措辞，不删具体风险列表和 source-edit ban。全文搜索必须仍能在 SKILL.md 直接看到 Probe-Only Boundary 和 Risk Confirmation。keep
C05把 means/gate 表格级内容下沉到 simulation-means.md 和 gate-levels.md；主文件保留 “required gate/means skipped means downgrade, never FULL PASS”。E05, E09, E14如果把 FULL PASS 限制也移走，最终声明容易过度。主文件保留唯一硬规则；reference 承担完整矩阵和例子。Audit existing evidence fixture 中，缺 G4 或 G3 时必须给 PARTIAL PASS 或 downgrade，不得 FULL PASS。low
C06把 browser adapter 细节只放在 simulation-means.md，主文件只保留 “browser tools are adapters, not top-level means”。E11高风险：agent 可能不读取 reference，回到 Chrome extension reinstall loop，或错误声称 signed-in Chrome coverage。保留带触发词的强指针：when effect mentions browser, Chrome, CDP, Playwright, profile, extension, Desktop, or Computer Use, read Browser Adapter Notes before choosing tools。Browser target-only prompt 必须选择 Playwright/browser MCP 或 Chrome DevTools 的正确边界，并显式 downgrade signed-in Chrome profile claim。high
C07把 sub-agent split examples 下沉到 scenario-matrix.md 的 Sub-Agent Fit，主文件保留 bounded sub-agent default 和 main-agent final claim ownership。E10, E12, E14可能损失并行 evidence collection 倾向，或 sub-agent 写入边界变弱。主文件保留 “use bounded sub-agents by default when independent evidence can be collected without shared mutable state”。写入路径和 source-edit ban 仍在主文件。包含 Web/IM/Track 三 surface 的 plan fixture 必须提出 sub-agent split 或记录 unavailable downgrade。medium
C08暂不移动 exact report format 和 unacceptable conclusions；后续若要下沉，先新建 references/reporting.md 并强制 SOP final step 读取。E14高风险：最终输出格式漂移、claim overreach、remaining risk 被省略。第一轮保留在主文件。压缩目标让位于 predictability。所有 forward-test 输出必须包含 Result, Effects Tested, Claim Proven, Means Used, Strategy, Subagents, Gates, Evidence, Cleanup, Remaining Risk。high
C09给超过 100 行的 reference 加短 TOC，并调整 context pointers 的 wording。E03-E13低风险。主要收益是减少 pointer miss 和 reference 内部查找成本。不改 reference 语义，只加目录和更明确的 “when to read”。引用文件 heading 一层可见；主文件每个 reference pointer 都有条件词。low

触发描述Description 是模型每轮可见的 context pointer。改得太泛会误触发，太窄会漏掉 live/browser/audit。用 BuddySwitch + simulated-user + probe-only + evidence-backed claim 形成边界；不要把普通测试、修 bug、CI 纳入。值得改，但必须 prompt fixture 审核。
低输入和 checkpoint把 defaults 下沉后，如果 agent 不读 reference，就会问太多问题或等待批准，破坏 “do the thinking”。主文件保留一句不可下沉原则，并在 SOP 第一段强制读 invocation reference。可以单一来源化，但 checkpoint 核心语义留在主文件。
