# Sender Reach Identity-Only Optimization Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rebuild the sender-side IM send path so 1-5 only needs identity-shaped send/reach inputs and Central IM write refs, with no `target_role_id`, `wake_actor`, or `wake_status` coupling in `send_im_message`.

**Architecture:** Central IM service owns durable conversation/message/state/event writes. Runtime projections resolve `target_identity_id` through a sender-side reach policy and call the pure message write contract. Actor target handling is not performed inside 1-5; it is handled by the separate 6-8 actor message handling plan.

**Tech Stack:** Python service modules under `scripts/env`, launcher IM projections under `tools/launcher`, unittest/pytest tests under `tests`, scoped residue checks in `tests/test_repo_consistency.py`.

## Bitter Principles Applied

Source: `docs/bitter`.

- Tool/service contracts must explain actual state impact; do not hide missing runtime semantics behind prompts.
- A semantic replacement requires behavior tests and scoped live-surface residue scans.
- Keep the product core clear: Central IM service owns message writes; interface layers project it.
- Avoid narrow fixes at the wrong boundary: do not add one-off actor/external cases inside `send_im_message`.
- Sliced implementation must preserve the full end-to-end promise; this plan is not complete product acceptance until the 6-8 plan is also implemented.

## Problem Statement

Current 1-5 send flow is not identity-only:

```text
message.send target_identity_id
  -> ActorImClient._send_target_identity
  -> actor_identity_for_current_send_target returns identity + role_id
  -> send_im_message(... target_role_id=..., wake_actor=...)
  -> Central IM write plus actor wake side effect
  -> response includes wake_status
```

This makes sender-side reach depend on target actor handling facts. It also blocks `ext-*` through an actor-only path before the request can be treated as a general identity target.

## Target Contract

1-5 contract:

```text
sender_identity + target_identity + content + reply_to
  -> Central IM writes direct conversation/message/state/events
  -> returns message_id + conversation_id + event_id + delivery_status
```

Constraints:

- `conversation_id` is not caller input. It is generated, reused, or derived from `reply_to`.
- `message_id` and `event_id` are generated by Central IM.
- `target_identity` may be actor or external at the service layer.
- If actor -> external active send is still blocked, the rejection must come from reach policy, not from an actor-only service signature.
- No `target_role_id`, `wake_actor`, or `wake_status` in `send_im_message`.

## Non-Goals

- Do not implement external outbound channel delivery.
- Do not implement actor target handling in this plan.
- Do not add a generic delivery engine, outbox, event bus, or compatibility adapter.
- Do not keep old and new `send_im_message` signatures side by side.

def identity_for_current_send_target(
    actor_rows: list[dict[str, Any]],
    target_identity_id: Any,
    *,
    field: str = "target_identity_id",
    active_identity_id: str | None = None,
) -> dict[str, Any]:

        status = _actor_status_from_runtime_row(row)
        if status in _BLOCKED_ACTOR_CONTACT_STATUSES:
