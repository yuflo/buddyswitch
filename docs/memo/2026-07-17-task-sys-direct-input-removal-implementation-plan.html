Task Sys Direct Input Removal

一次 forward-only 清理：让 direct Actor input 只走 ActorSession / AppServer，把 user.input 从 Task Sys 的入口、运行时语义和正向测试模型中彻底移除。

Artifact job

让实施者可以从当前事实出发，按 RED → GREEN → REPLACE → ACCEPT 的最短路径完成清理，并留下可复现证据。

Acceptance sentence

Direct Actor input reaches only ActorSession / AppServer. Task Sys has no user-input ingress helper, CLI, or runtime prompt branch; its domain rejects user.input; controlled IM / Track ingress remains intact; current tests use user.input only in explicit negative guards.

Decision and boundary

Selected · direct REBUILD

删除 Task Sys 的 direct-input 写入口与专用解释分支，在 domain owner 明确拒绝该 source，并替换所有正向 fixture。最终只保留一个产品事实。

Rejected · 仅断开产品调用

只保证 ActorSession 不调用 Task Sys、但继续保留 helper / CLI / domain 接受能力，会让退休模型仍然可达、可发现。

Rejected · 重命名或重新解释

把 user.input 解释为未来受控文本入口会继续混淆直接交互和可治理 inbound。未来若需要，必须以新的受控 source 契约引入。

Out of scope

不改变 lifecycle 状态机、side → parent handoff、parent 并发处理策略、relation analysis，也不重写历史 memo。

唯一允许的残留：Task Sys domain 与测试可以明确写出 user.input，但只能用于“拒绝它、证明不会创建任务”的负向契约；不能作为可处理 source、fixture 或 task ID 来源。
