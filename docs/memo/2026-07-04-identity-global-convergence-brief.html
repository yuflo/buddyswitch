1. 任务目标

把 actor/external 静态身份信息收束到一个 owner，禁止其它模块继续维护第二套静态身份 schema。

Objective

actor 静态身份

actor 的静态身份资料统一由 ActorIdentityProfile 表达。

{"identity":{"id":"act-...","type":"actor"},"role_id":"pm","label":"PM"}

external 静态身份

external 的静态身份资料统一由 ExternalIdentityProfile 表达。

{"identity":{"id":"ext-...","type":"external"},"display_name":"..."}

删除旧包装

旧 actor 静态身份 owner 直接删除，不保留兼容轨。

actor_profile.py / ActorAddress -> removed

2. 模块边界

关键是区分“静态身份资料”和“运行时/业务事实”。前者只能进 identity，后者可以在所属模块维护。

Boundary
信息类型 唯一归属 原因
identity id / type env.domain.identity.IdentityRef 所有模块都要引用同一套“谁”的 schema。
actor role_id / label / created_at ActorIdentityProfile 这是 actor 静态资料，不能散落在 runtime、daemon、web、IM。
external display_name / created_at ExternalIdentityProfile 这是 external 静态资料，connection 只能保存连接事实。
role definition buddyswitch/manifest.toml manifest 定义 role 的产品能力；identity profile 引用 role_id。
endpoint / heartbeat / online status daemon registry 这是投递状态，不是静态身份。
thread_id / workspace_dir / instance_root launcher instance state 这是运行实例状态，不是静态身份。
conversation / message / event / state IM product 这是通信业务事实，只引用 identity。

3. 当前问题审查

当前系统的问题不是没有 identity id，而是静态身份 owner 太多。

Current Risk

第二 owner

  • scripts/env/tool_runtime/actor_profile.py 定义 Actor、Role、ActorAddress、ActorProfile。
  • daemon registry 用 actor_address 保存 actor 静态身份。
  • web / product surfaces 传播 active_actor 作为身份结构。
  • IM participant 用 kind + actor_address / external_id 重新定义身份。

为什么会卡住

  • 删除一个旧字段后，静态身份会转移到另一个模块继续复制。
  • daemon、IM、web 会各自解释 actor 是谁。
  • 后续 actor/external 统一通信会被旧 actor-only 结构拖住。
  • 测试只能覆盖字段变化，不能证明 owner 收束。

4. 目标模型

identity 模块成为静态身份入口；其它模块只消费 identity。

Target Model
Identity Module 创建/校验 actor 与 external profile。
Runtime 读取 current identity/profile，不定义 actor profile。
Daemon 保存 delivery state，引用 identity。
Product Surfaces owner/author/mention 使用 identity id。
Task B 通信切换消费这个 invariant。

允许的静态 profile

ActorIdentityProfile { identity: {"id": "act-...", "type": "actor"}, role_id: "pm", label?: "...", created_at?: "..." } ExternalIdentityProfile { identity: {"id": "ext-...", "type": "external"}, display_name?: "...", created_at?: "..." }

禁止的替代 owner

Actor / ActorAddress / ActorProfile active_actor as static identity object participant.actor_address participant.external_id daemon registry actor_address

5. 影响面

A 的改造范围超过 IM。它必须清理所有会维护 actor/external 静态资料的模块。

Impact

Identity core

  • scripts/env/domain/identity.py
  • 新增/强化 profile validation
  • 删除 IM legacy 反向依赖

Runtime context

  • scripts/env/tool_runtime/context.py
  • scripts/env/tool_runtime/role_auth.py
  • delete scripts/env/tool_runtime/actor_profile.py

Consumer cleanup

  • daemon / web / Track / Artifact / Comment
  • result helpers and response contracts
  • tests and residue guard

6. 不在 A 中解决

A 只建立唯一静态身份 owner，不负责具体通信行为扩展。

Non-goals

不做通信能力

  • 不开放 actor -> external 主动发送。
  • 不补 iMessage actor 主动发 external route。
  • 不扩展 reply_to 规则。

不吞运行态

  • identity 不维护 endpoint、heartbeat、online status。
  • identity 不维护 thread、workspace、browser port。
  • identity 不维护 IM conversation/message state。

7. A 的验收标准

验收重点是唯一 owner 成立，以及所有第二 owner 被删除。

Acceptance

行为验收

  1. env.domain.identity 能创建/校验 IdentityRef、ActorIdentityProfile、ExternalIdentityProfile。
  2. runtime context 能从 identity profile 得到当前 actor identity 和 role context。
  3. role auth 仍能基于 role_id 和 manifest 判断权限。
  4. web/status/context 输出不再生成第二套 actor 静态身份结构。

残留验收

期望：除专门 residue test 的 forbidden-term 列表外无 live 命中。

8. 与 Task B 的关系

B 不应该重新设计身份。B 只消费 A 的完成态，把通信链路切到 identity 引用。

Dependency
Task 完成态 对另一个任务的要求
A. Identity 全局收束 唯一静态身份 owner 成立，第二 owner 删除。 给 B 提供不可绕过的 identity profile contract。
B. Communication / IM cutover runtime、daemon、IM、product surfaces 只引用 identity。 不能新增任何身份 schema；缺资料时查 A，不在 B 内复制。
