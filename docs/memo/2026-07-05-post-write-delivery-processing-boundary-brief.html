BuddySwitch IM Architecture Brief · 2026-07-05

Post-write Delivery / Processing Boundary 收束任务

这个 HTML 用来明确下一阶段任务：在 Central IM message 写入之后，将目标侧 delivery mechanism 与 target-side processing 拆清楚， 让 actor 与 external 的差异分别收束在确定模块边界内，而不是继续回流到 reach 或 message write。

当前状态 Write 已 identity-based send_im_message 只写 conversation/message/event/state，已不接 target_role_id 或 wake_actor。
本次目标 拆开 Delivery 与 Processing Delivery 负责送达目标侧；Processing 负责目标侧拿到后怎么消费。
关键边界 External Ingress 不属于 Delivery external 发进来是 ingress；BuddySwitch 发给 external / 供 external 读取才是 delivery。
非目标 不直接开放 actor -> external 本次先收束 post-write 架构边界，不把 reach 和 channel routing 一起扩进去。

1. 任务目标

目标句

将 Central IM 写入之后的 delivery mechanism 与 target-side processing 明确拆分，形成 actor / external 都能接入的 post-write 模块边界。

为什么现在做

Reach 与 write 已经基本解耦。下一步阻塞点不再是 message 能不能写，而是 target 侧收到 message 的机制与收到后处理逻辑仍未形成统一边界。

Delivery mechanism

message 已写入后，系统如何让 target 侧收到通知或可消费事件。

Target-side processing

target 侧收到 message 后，内部如何消费这条 message。

External ingress

external user 发消息进 BuddySwitch。它是入口，不是 delivery。

5. 系统边界矩阵

Reach

判断 sender 能不能发给 target identity。

输出 identity / status。
不写 message，不唤起 actor，不调用 channel。
Central IM Write

持久化 message、conversation、state、event。

只依赖 identity payload 与 content。
不包含 delivery adapter，不包含 processing。
Delivery

message 写入后，向目标侧提供可消费信号。

actor: mailbox；external: connection events；channel 经由 im-api。
不创建 Task Sys 语义，不解释用户意图。
Actor Processing

actor 本地拿到 im.message.created 后怎么处理。

当前接 task_sys_ingress。
后续可继续收束处理器接口，但不回写 sender path。
External Delivery

把 BuddySwitch message 暴露给 external connection；channel 通过 im-api 读取并投递到外部通道。

当前 read/ack；channel adapter 不绕过 im-api。
不代表 external 发进来的入口。
External Ingress

external user 发消息进 BuddySwitch。

属于 send surface / ingress。
不能和 BuddySwitch -> external delivery 混在一个概念里。

6. 实施要点

建议实施顺序

1
定义 post-write delivery contract

输入限定为 target_identity、message_id、conversation_id、event_id。

2
抽出 ActorDelivery

保留现有 wake_im_actor 能力，但把它命名和边界收束为 actor delivery adapter。

3
明确 ActorProcessing

ImMessageCreatedHandler 是 target-local processing 边界，当前消费者是 Task Sys。

4
抽出 ExternalDelivery

先承接 read_events/ack_event 语义；channel adapter 继续作为 /api/im/* 客户端。

5
加 residue tests

防止 reach/write 再引入 wake_actor、Task Sys、channel 内部语义等处理细节。

关键约束

不要把这次任务扩成 actor -> external 主动发送。

本次只收束 post-write 边界。external active-send reach 与 external delivery adapter 细化是后续任务。

不要引入通用 event bus。

先用现有 message refs 和明确 adapter；如果没有重复真实需求，不做平台化抽象。

要保留当前已验证主路径。

actor -> actor send、actor reply actor、actor reply external、external -> actor 都要保持测试通过。

7. 验收标准

边界验收
  • Reach 不引用 delivery / processing。
  • Central IM write 不引用 delivery adapter。
  • Delivery 不调用 Task Sys 语义。
  • Processing 不要求 sender 传 target runtime 字段。
行为验收
  • actor target message 仍进入 mailbox local trigger。
  • actor processing 仍进入 task_sys_ingress。
  • external connection 仍可 read / ack visible events。
  • actor active send external 仍不在本次开放。
测试验收
  • focused IM suite 通过。
  • repo consistency 通过。
  • residue scan 无旧耦合字段。
  • 新增 delivery / processing 边界测试覆盖 actor 与 external。
