Task lifecycle 状态转移

图中的方框是 Task Status；箭头是越迁动作。除此之外没有第二套 Task 进展状态。

Task Status = Task 当前进展；Lifecycle = Status 之间的推进。

in_progress 是状态分组，不能单独落地。一个进行中的 Task 必须明确处于 side_processing、awaiting_parent 或 parent_processing。

Review decision

Execution facts 不是第二套状态

processor、handoff、frame、prompt、event 和 cleanup 只记录执行事实；Task 进展只由 canonical status 表达。

Check

Progress Check 可能推进，也可能保持原状态

例如 parent Progress Check 判断继续工作时，Task 仍是 in_progress.parent_processing；判断完成时才越迁到 completed。Check 本身不是状态。

Boundary

Execution facts 不再定义 lifecycle

processor、handoff record、frame、prompt、event 和 runtime cleanup 只能记录执行事实，不能与粗粒度 status 组合出另一套“隐式状态”。

New line

independent

当前 task 和已有 actor-level task 没有需要 Task Sys 表达的执行关系。

Effect: 正常执行。`target_task_id = null`，主线锚点是 self。
Merge

contributes_to

补充、约束、修正、细化、素材追加。目标 task 后续必须能看到它。

Effect: 当前 task 快速吸收/close，向 target 追加 event/context。
Wait

depends_on

当前 task 需要目标 task 先产出，否则无法执行或会误报。

Effect: 当前 task waiting/blocked，直到 target completed。
Pause target

blocks

当前 task 会暂停目标 task，例如“先别做，先确认/改方向”。

Effect: target 被 Progress Check 强提醒或暂停；当前 task 先处理。
Replace

supersedes

当前 task 替代目标 task。目标 task 不应继续按旧方向执行。

Effect: target canceled/superseded，当前 task 成为新执行主线。
Design choice Decision Reason
Graph scope 不维护全连接图 每个 task 只需要 primary relation。完整图会让模型做过重推断，也难以防错。
Candidate source 优先 active/recent objective candidates 不要每次把所有 actor tasks 交给模型比较。候选集应由程序收窄。
Objective anchor 程序派生，不让模型自由维护 避免链式漂移和循环。模型只选 kind、target、note。
Cross-role relation 不进 Task relation 跨 role 协作依赖 Track，task 是 actor-level 局部执行单元。
Self-contained memo. No external assets or runtime dependencies.
