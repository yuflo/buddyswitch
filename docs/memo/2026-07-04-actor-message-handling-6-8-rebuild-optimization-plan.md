# Actor Message Handling 6-8 Rebuild Optimization Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rebuild actor-target IM handling so 6-8 accepts only target actor identity plus Central IM message refs, derives actor role from identity profile, uses daemon reachability only for runtime endpoint facts, and submits a local actor inbound event without relying on sender-provided `target_role_id`.

**Architecture:** 1-5 produces durable Central IM refs. 6-8 is a message-owned actor handling adapter that bridges those refs to the target actor mailbox. The target actor runtime consumes `im.message.created` as a local inbound event; Task Sys remains only the current runtime consumer behind that local boundary.

**Tech Stack:** Python launcher/runtime modules under `scripts/env/tool_runtime` and `tools/launcher`, identity profiles under `scripts/env/domain/identity.py` and `scripts/env/repos/identities.py`, unittest/pytest tests under `tests`.

## Required Precondition

Implement the sender reach identity-only plan first. This plan assumes:

- `send_im_message` no longer takes `target_role_id`.
- `send_im_message` no longer takes `wake_actor`.
- `send_im_message` response no longer includes `wake_status`.
- Message write responses still include `message.id`, `message.conversation_id`, and `event_id`.

## Bitter Principles Applied

Source: `docs/bitter`.

- Keep the shared boundary stable and boring: `mailbox.local_trigger` is the stable local runtime ingress; business variation stays in the message-owned handler.
- Built-in product model belongs below projections: Central IM writes messages, message inbound owns IM local event registration, daemon only provides runtime reachability.
- Residue cleanup needs behavior proof and surface proof; tests must reject sender-supplied role in the 6-8 payload.
- Do not claim sliced completion until actor-target send crosses write -> handling -> local runtime consumption.

## Problem Statement

Current 6-8 starts inside `send_im_message`:

```text
send_im_message writes message
  -> constructs wake payload with target_role_id
  -> calls wake_actor
  -> wake_im_actor requires target_role_id in payload
  -> check_reachability returns record and endpoint
  -> mailbox.local_trigger(identity_id, role_id, im.message.created)
  -> ImMessageCreatedHandler consumes local trigger
```

Problems:

- Sender-side message write supplies `target_role_id`.
- `wake_im_actor` cannot run from `target_identity_id + message refs` alone.
- 6-8 can accidentally treat daemon registry `role_id` as a static identity source.
- `wake_status` naming leaks the old coupling back into caller-facing semantics.

## Target Contract

6-8 contract:

```text
target_identity_id + message_id + conversation_id + event_id
  -> identity profile lookup gives role_id
  -> daemon reachability gives online status and mailbox endpoint
  -> mailbox.local_trigger submits im.message.created to target actor
  -> target actor runtime receives local inbound event
```

Allowed internal data:

- `target_identity_id`
- `message_id`
- `conversation_id`
- `event_id`
- optional `correlation_id` generated by the adapter
- target-side `role_id` derived from `env.repos.identities.get_actor_identity_profile`, validated by `ActorIdentityProfile`
- mailbox endpoint from `actor.check_reachability`

Forbidden inputs:

- sender-provided `target_role_id`
- sender-provided mailbox socket
- sender-provided runtime role
- message content embedded in trigger payload

## Non-Goals

- Do not implement target external outbound delivery.
- Do not rebuild Task Sys in this plan.
- Do not add a generic delivery engine, outbox, event bus, or new shared router.
- Do not remove `target_role_id` from all daemon trigger types; track comments, scheduled triggers, and other local runtime triggers are outside this IM-specific 6-8 path.
