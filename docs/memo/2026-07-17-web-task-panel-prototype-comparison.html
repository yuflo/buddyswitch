Product interface research

外部模式：保留历史，但降低历史的默认噪声

调研不是寻找可复制的皮肤，而是验证列表密度、终态位置和异常信号的常见处理方式。

GitHub Actions

状态图形在前，标题与上下文居中，时间在右

公开 workflow run 列表把成功、失败、需要操作作为第一视觉信号；每条 run 保持单一行组，不把每条记录做成独立卡片。对 BuddySwitch 的启发是：状态要先扫到，task id 应退为次级元数据。

公开运行列表示例

Todoist · completed tasks

终态被保留，但默认退到列表底部或独立日志

官方帮助说明已完成任务会保留；在项目/Today 中按需显示在当前列表底部，日志则提供只读回顾。对 BuddySwitch 的启发是：不要让 completed 消失，也不要让它压过 active。

查看官方说明

Vercel Deployments

当前与历史属于同一对象集合，按状态与时间阅读

官方文档明确 dashboard 管理 current and previous deployments，并按 branch、date、environment、status 过滤。对这个小面板而言，不需要照搬过滤器，但应保持“终态仍属于 Task 集合”的连续心智。

Backend fit

后端已保留终态，缺口只在 Web 投影

所有原型均为只读；没有假设新的生命周期动作，也没有使用当前 external-safe contract 不存在的标题、描述或执行细节。

最小 owner-correct 后端增量

由 Task Read 明确产出 terminal_tasks / terminal_count（completed + canceled，仍使用同一 external allowlist）；Web 只负责切到最近 5 条。

明确不做

不在 Web 复制生命周期规则；不引入分页、搜索或新存储；不暴露 execution、events、summary；不添加 close/cancel/retry 操作。

Browser iteration log

原型会按真实 rail 约束做多轮收敛

这里记录从现状、视觉探索到浏览器宽窄屏与交互 QA 的实际修正，不把“做过截图”当成设计质量本身。

Baseline

现有面板只是一张运行摘要卡

  • 300px rail 已经同时承载 Capability、Runtime、Task、Track。
  • Task 只显示 active/recoverable 各第一条。
  • 设计不能靠增加新页面和大控件解决。
Round 1

从三种信息架构开始，而非三套配色

  • Stack：历史折叠。
  • Ledger：当前与历史连续。
  • Switch：Current / Recent 共用高度。
Round 2

剔除后端不支持的“聪明文案”

  • 不显示耗时异常原因或自动重试承诺。
  • 异常只表达 recoverable membership。
  • 所有行只用五个 external-safe 字段。
Round 3

宽屏首屏从“报告感”收回到“评审板”

  • 标题上限从 62px 收到 48px，首屏更早进入真实原型。
  • rail 样板高度收至 455px，三案与选择按钮可在 1440×1024 同屏比较。
  • 选择 dock 默认隐藏，避免遮挡 C 案。
Round 4

交互与窄屏完成浏览器验收

  • 情景、历史展开、行详情、Show more、Current/Recent 与选择均通过。
  • 复制改为同步 fallback，避免受限 Clipboard API 悬挂。
  • 390×844 下 scrollWidth 等于 clientWidth；控制器自然换行，无横向溢出。
尚未选择方向建议先在三种情景中操作三个原型，再做选择。
