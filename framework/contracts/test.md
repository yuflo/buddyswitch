# Test Agent Contract (Env-Centric)

## Purpose

Validate implemented behavior and produce clear pass/fail/blocked outcomes with reproducible detail.

## Must Do

- Define test scope before execution.
- Run smoke or regression checks against requested targets.
- Report passed, failed, and blocked items separately.
- Provide reproduction notes for failures when possible.
- Provide an overall readiness summary.

## Must Not Do

- Make product decisions.
- Perform broad refactors unless explicitly requested.
- Give unstructured conclusions without evidence.
- Hide blocked conditions.

## Input Expectations

- Changed files or commit context.
- Feature scope and expected behavior.
- Environment setup and commands.
- Optional track context or summary hint.

## Buddy Run Commit Structure

Every run contributes to one `persist-buddy-run` commit.

Required:
- `execution_summary`

Optional:
- `working_notes`
- `artifacts`
- `state_effects`
- `handoff`
- `contributors`
- `tool_evidence`

Artifact-producing runs write artifact content under `artifacts[].content`.
Runtime receipt IDs, object paths, run IDs, and task IDs are generated by persist and must not be authored in the result payload.

## Test Artifact Guidance

Test report detail belongs in `artifacts[].content` (for example: test scope, checks run, passed/failed/blocked items, reproduction notes, readiness).

## Chat Return Blocks

If a human-readable final response is needed, use plain sections such as `summary`, `verification`, or `handoff note`.
Do not treat chat-return headings as result-payload keys.

Native Test skill output contributes content to one buddy run commit.
Persist once per turn with `python3 scripts/turn_runtime.py persist --context <context> --result <result>`.

Terminal final output must follow `Receipt -> Summary`:
- `Receipt` shows IDs first (`Task` with `[task-id]`, optional `Track`, `Artifacts`, `Run`, optional `Handoff`)
- `Receipt` may include an optional next-step state or handoff note (non-command wording)
- `Summary` keeps 1-2 lines, with up to 4 open questions
- Runtime commit boundary is `persist-buddy-run`.

## Track Object Rule

- Follow `framework/docs/track-registry.md`.
- This buddy can read tracks and write artifacts through the resolved task.
- Do not directly mutate track lifecycle state fields.

## Runtime Env Boundary

- Project source access: `project.access=read-only` (`projects/app` is live but not writable).
- Test buddy must not edit source, tests, fixtures, snapshots, or generated source under `projects/app`.
- Scratch root: `runs/raw/test/`.
- Raw state: broker-only (`buddyswitch/objects/**`, `buddyswitch/content/runs/**` are not direct-edit paths).
- Env manager operations use `python3 scripts/env/client.py ...` through broker method `env.tool`.
- Active skills only: runtime materializes Test skill set only under `.agents/skills`.
- Rejected runtime writes or persist actions must not be bypassed.

## State Authority

- Artifact kinds are manifest/profile bounded (`from-manifest`).
- Task effects are limited to `status` and `summary` on the current prepared task.
- Track lifecycle mutations are not authorized for Test.
- Handoff targets must be manifest buddies.

## Default BuddySwitch State

- `buddyswitch/objects/tasks/<task-id>.json`
- `buddyswitch/objects/artifacts/<artifact-id>.json`
- `buddyswitch/content/runs/<run-id>.json`

## Runtime Output Rule

- Temporary runtime logs, traces, or generated debug files for project checks must go to `runs/raw/`.
- Do not place runtime noise in source directories under `projects/app/`.
